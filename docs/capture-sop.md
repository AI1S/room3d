# 拍摄 SOP（手机采集 → 高斯泼溅）

> 目标：一次拍成，重建不糊、不重影、方向不乱。**失败重拍的成本远高于多花 2 分钟。**

## 一、开拍前 60 秒检查

- [ ] 手机电量 > 30%，存储 > 5 GB，开飞行模式（避免来电中断）
- [ ] 1080p / 60fps；**不要用 0.5x 超广角**，用主摄 1x，全程不变焦
- [ ] 锁 AE / AF / 白平衡（部分机型需第三方相机 App）；关 HDR、关美颜、关防抖裁切
- [ ] 拉开窗帘但**避免逆光直拍窗户**；只开一盏主灯，别开彩色氛围灯
- [ ] 收拾场地：床帘拉开、桌面清空、地上不放杂物、**收走带屏幕/单据的私人物品**
- [ ] 画面里**不能有人**（室友要出镜或入画需先征得同意；公开前再自查一遍）

## 二、走位（2–3 分钟，像端着一杯水慢慢走）

1. **原地慢转 360°**（约 20 秒）：站房间中心，手机举到胸口高度，转的时候不要停、不要晃。
2. **沿中轴往返 2 遍**：从门口走到窗边再走回来，速度 ≤ 0.5 m/s，每走 3 步停 0.5 秒。
3. **补拍低处**：蹲下，镜头对着地面/床底边缘扫一遍（W5 会说"床底看不到"，这里能提高覆盖）。
4. **补拍高处**：举高，对着天花板和墙角扫一遍。
5. **回到起点，静止 3 秒**：闭合回路，后面 COLMAP / 位姿估计会感谢你。

**全程不要**：快速转身、边走边晃、突然变焦、进门出门、把手机贴到墙上。

## 三、拍完自查（30 秒）

- 回放：画面有没有大面积糊（走动太快）、有没有出现上一帧残影
- 有没有拍到人脸、门牌号、快递单、准考证、聊天屏幕
- 视频时长 2–3 分钟、体积通常 200–500 MB（1080p60）

## 四、抽帧（本仓库脚本）

```bash
py scripts/extract_frames.py --video D:/scan.mp4 --out data/scans/mine/frames --fps 2
```

- 默认 **2 fps**：2 分钟视频 ≈ 240 帧，够 splatfacto / COLMAP 用；
- 如果走动快、画面糊，改 `--fps 3`；如果帧太多跑不动，降到 `--fps 1`；
- 需要缩放到 1280 宽：加 `--width 1280`。

## 五、重建（本机 4090 Laptop 16 GB）

| 方案 | 装起来 | 优点 | 缺点 |
| --- | --- | --- | --- |
| **Postshot**（Windows GUI） | 下载即用 | 最省事，直接导出 .ply/.splat | 商业化，免费版有水印限制 |
| Luma / KIRI 等在线 | 上传 | 零配置 | 免费额度有限，隐私要评估 |
| nerfstudio splatfacto | 需要 CUDA + tiny-cuda-nn | 完全可控，能改参数 | **Windows 编译 tiny-cuda-nn 很痛**，建议 WSL2 |

训练时长参考：80–120 ㎡ 三居 ≈ 20–40 分钟（L4/A10 级 GPU），本地 4090 Laptop 类似量级。

## 六、常见失败对照

| 现象 | 原因 | 对策 |
| --- | --- | --- |
| 重建出来糊成一团 | 走太快 / 光线太暗 / 大面积纯白墙无纹理 | 放慢 + 补光 + 对着有纹理的家具多停留 |
| 房间"躺平"或倒挂 | 数据集是 Z 轴朝上 | 页面点「修正朝向」 |
| 家具像被撕碎 | 遮挡太严重（走位没有绕开） | 绕家具半圈再走，别只从一个方向拍 |
| 窗户/镜子是黑洞 | 3DGS 对高光和镜面反射无能为力 | 记进"无法查看"，别硬补 |
| 尺寸差很多 | 3DGS 尺度不可观测 | 见下：放一个已知尺寸参照物 |

## 六点五、实测反例：一条"能拍但重建不出来"的视频

2026-11-23 拿一条真实宿舍视频（720×1280 竖屏，30fps，169 s，36 MB，H.264，side_data 旋转 -90°）跑
COLMAP 4.2.1 + Brush，**建图基本失败**。留在这里当反例：拍之前对照一眼，就知道哪些坑会直接让重建报废。

### 1. 两轮抽帧对照（同一段视频）

| 项目 | 2 fps | 10 fps |
| --- | --- | --- |
| 抽帧 | 322 张（整段剔除室友出镜的 37–45 s） | 1604 张（剔除 36.5–45.5 s） |
| 特征提取 / 匹配耗时 | — | 0.66 min / 3.85 min（RTX 4090 Laptop 16 GB） |
| 匹配质量 | 2387 对图像里 **inlier 中位数 0**，只有 607 对 > 50 | 未逐对统计 |
| mapper | **7 个碎片模型，每个只注册 2 张图**，日志 `Discarding reconstruction due to no initial pair` | **194 / 1604 帧注册（12%）**，16279 个稀疏点；本轮**中途手动停止**，日志末行 `num_reg_frames=190`，所以 194 是下限不是终值 |
| 结论 | 位姿完全解不出来 | 能解出局部，覆盖率太低，不够训练 |

> 数据来源说明：以上数字来自当时的 COLMAP 终端输出与 SQLite 统计（`images` / `matches` 表）。
> 原始 `_diag/` 日志、诊断脚本和 911 MB 数据集在测试后被清理掉了，**现在只能复述结论、不能给出逐帧明细**。
> 这是"先删证据、后写文档"的教训，已记进 [log.md](log.md)。

### 2. 三种情况要说清：别把"没匹配上"叫"位姿漂移"

| 现象 | 观测证据 | 机理 |
| --- | --- | --- |
| **帧间重叠不足**（本轮主因） | 2 fps 相邻帧间隔 0.5 s，inlier **中位数 0** ⇒ 相邻帧根本没匹配上 | 0.5 s 内转过的角度超过竖屏水平视场（约 50°），两帧拍的是两个几乎不相交的方向；走动带来的平移也过大 |
| **弱纹理白墙** | 150–160 s 贴墙段 sharp（灰度梯度能量）**0.7**，全片中位 8.26、p10 4.01 | 白墙提不出稳定关键点，这段本身就是废帧，帧率再高也救不回来 |
| **位姿漂移**（本轮并未出现） | 漂移的前提是"跟踪已经建立"；本次连匹配都没建立 | 漂移是跟踪成功后误差逐步累积，"压根没匹配上"是另一回事 |

**汇报时的说法**：这条素材的失败原因分两层——拍摄层面是"帧间无重叠 + 近距特写"，
素材层面是"整段无纹理废帧 + 有人物出镜"。**不要笼统说成"弱纹理导致位姿漂移"**，概念会对不上。

### 3. 三个可精确定位的具体证据

1. **室友出镜 37–45 s**（2 fps 下是第 74–90 帧，1-based）：坐在桌前用白色笔记本打游戏，占画面右侧约 1/4。
   既是隐私红线（未经同意不得发布），也是动态物体（3DGS 会把它渲成半透明鬼影）。**抽帧时必须整段剔除**——
   当时的做法是抽完帧按帧号删（2 fps 下删第 73–89 帧，0-based，共 17 帧；留 0.5 s 余量就是 36.5–45.5 s 这段）。
   `scripts/rebuild.sh` 目前**没有内置区间剔除**，需要时先抽帧、手动删掉这段，再把 `frames/` 交给 COLMAP。
2. **150–160 s 贴白墙**：手机几乎贴着墙走，整段 sharp≈0.7（全片中位 8.26）。
   判据：sharp < 5 的帧直接丢；连续一段都 < 5，说明这段走位无效。
3. **全程无静止帧**：相邻帧灰度差（200 px 缩略图）< 1.0 的占比 **0%**，均值 37.67。
   COLMAP 找不到一对可靠的初始图像对，这就是"7 个碎片模型"的直接原因。

复测方法（换自己的视频也能跑）：

```bash
# 1) 抽帧
ffmpeg -i data/test1.mp4 -vf fps=2 -q:v 2 frames/frame_%05d.jpg
# 2) 逐帧算两个指标并导出 CSV：
#    sharp = 灰度梯度能量（相邻像素差平方的均值）
#    diff  = 与前一帧的平均绝对差（先缩到 200 px 宽再算）
#    阈值参考：sharp < 5 丢帧；帧差中位 < 12 偏慢（好事），> 30 说明扫得太快。
```

> 判据参考本次实测：正常慢走的视频，帧差中位数应在 10–25 之间，并且有若干帧接近 0（停顿）。

**致命组合 = 快速扫视 + 近距离特写 + 从不停顿。** 反过来说，只要做到：

- 单帧转过的角度 < 视场的一半（竖屏约 25°/s 以内；横屏可放宽到 35°/s）；
- 任何物体离镜头 ≥ 1 m，能看到"整面墙 + 地面 + 天花板"的关系；
- 每隔几秒有短暂停顿（0.5 s 就够），给特征匹配一个稳定的锚点；

COLMAP 才有可能解出尺度一致的位姿。**如果只想记一句话：慢到你觉得无聊为止。**

> 抽帧 fps 的选择也跟着变：正常慢走 2 fps 就够；如果手持较快，先抽 10 fps 跑一遍 SfM，
> 建图成功后再按 `--subsample-frames` 降采样给 3DGS 训练（详见 README 的重建章节）。

## 六点六、拍摄质量 → 重建结果：三个真实样本

| 样本 | 视频 | 抽帧 | COLMAP 注册 | 结果 |
| --- | --- | --- | --- | --- |
| 反例 1 | 720p30 竖屏 2 分 50 秒，贴脸特写、室友入镜 | 2 fps / 322 帧 | **每个模型只注册 2 张**，7 个碎片模型 | 只能重建出窗帘残片，无房间结构 |
| 反例 2 | 1080p30 竖屏 4 分 12 秒，走完全屋但全程不停顿 | 6 fps / 1514 帧 | 1468 张（97%）、重投影 1.298 px | **重建成功**：上下铺、蓝柜、门都能认出来 |
| 对照 | 同上，只改了 Brush 的训练数据目录 | — | 同上 | 相机/初始点错配 → 整体飘在相机外，网页里一团雾 |

可迁移的三条结论：

1. **帧间重叠 > 一切参数**：2 fps 的快速扫视直接全军覆没，6 fps 才救回来；抽帧帧率不够时，先怀疑重叠再怀疑算法。
2. 画面可以"糊一点"，但**不能一直在动**：这条视频零静止帧（相邻帧差中位 35.6），依然注册 97%，说明慢走比停顿更重要。
3. 重建出来是雾/条纹，**先分清是"拍摄问题"还是"工具问题"**：拿同一份 PLY 直接拖进页面看，能一眼分开这两类（见 docs/log.md 4.7）。

## 七、尺度校正（W3 才做，但拍摄时就要配合）

在房间里放一个**已知尺寸参照物**（A4 纸 297×210 mm，或标准门宽 0.9 m），
拍摄时让它出现在画面里至少 5 帧。W3 会用它把点云缩放到真实米制，
并输出一张「实测 vs 重建」误差表——这是评委最容易认可的自研技术点。
